# Kimelow.gd v5 — обновление оригинального многстраничного сайта v4

## Быстрый старт

Распакуйте архив и откройте `index.html`. Добавление попыток и темы работают локально без регистрации. Для разработки и подключения онлайн-аккаунтов лучше использовать локальный сервер: `python -m http.server 8000`, затем `http://localhost:8000`.

**Death Tracker:** на главной и странице `tracker.html` есть кнопки +1, +10, +50, +100, «+ Своё» и «Исправить» (последняя заменяет общее число попыток, а не добавляет). История сессий хранится в данных. Чтобы сменить тему и имя, нажмите «⚙ Профиль / тема» на любой странице.

## Реальные аккаунты и синхронизация с Supabase

1. Создайте проект на https://supabase.com.
2. В SQL Editor выполните содержимое `supabase.sql`. Включены **RLS-политики**: любой может читать только публичные имена из `profiles`, а данные `player_data` принадлежат конкретному пользователю.
3. В Supabase → Project Settings → API найдите Project URL и `anon` / **publishable** key. Вставьте в `config.js` (только публичный клиентский ключ, **никогда** `service_role` / secret).
4. В Supabase → Authentication → URL Configuration задайте Site URL на фактический адрес размещённого сайта и Redirect URLs для этого домена. При тестах укажите localhost. Email confirmations могут быть включены: тогда после регистрации подтвердите письмо.
5. Разместите папку целиком на HTTPS-хостинге (например, Netlify или GitHub Pages), чтобы ей могли пользоваться разные игроки. Статический ZIP сам по себе не является интернет-сайтом.
6. На сайте откройте «⚙ Профиль / тема», зарегистрируйтесь или войдите. Попытки и рекорды сохраняются в Supabase и загружаются после входа с другого устройства.

## Важные ограничения

- **Существующая гостевая статистика не загружается автоматически в новый аккаунт.** Это намеренное решение против случайной перезаписи чужих записей и смешивания данных. Гостевые данные сохраняются локально для возврата после выхода.
- Имя локального профиля сохраняется только в браузере; имя авторизованного игрока и цвет темы сохраняются в Supabase.
- Сведения профиля в базе разрешено читать публично, но отдельной страницы просмотра чужих рекордов пока **нет**. Рекорды изолированы RLS и видны только владельцу.
- Для синхронизации нужен доступ в интернет и работающая конфигурация Supabase. При отсутствии сервера доступна локальная версия. В случае ошибки синхронизации не закрывайте страницу, пока не решите проблему.
- Для настоящего публичного сервиса требуется тестирование под нагрузкой, настройка защиты от злоупотреблений и резервного копирования БД.
- Храните резервные копии прежнего ZIP / localStorage, особенно перед первым входом в аккаунт.
